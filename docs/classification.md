# 分类体系与分类树

> 版本 v0.1 · 2026-10-25 · 分类规则与题干的唯一权威

## 9 类总览

| cat | 中文 | 定义 | 典型来源 |
|---|---|---|---|
| `homework` | 作业 | 课程作业、实验、报告、习题提交（有明确提交物和课程归属） | 课程群 · 老师/课代表 |
| `exam` | 考试 | 考试安排、补考、成绩/绩点、考点范围、考试类日程（含"期末考试总体规划"） | 课程群/年级群 · 老师/教务处 |
| `competition` | 竞赛 | 学科竞赛、创业大赛、招新选拔（有评选/排名性质） | 年级群/竞赛群 |
| `research` | 科研 | 科研训练项目流程（SRTP/大创/国省创）：立项发布、选题、开题、中期、结题答辩、分数公告 | SRTP群/学院群 · 负责老师 |
| `exchange` | 国际交流 | 国际交流、访学、交换生、国际会议、奖学金（涉外） | 年级群 · 国际处/学院 |
| `lecture` | 讲座活动 | 参加型：讲座、宣讲会、大会、团建、运动会集合、赛事观摩（有时间地点、去参加） | 年级群/社团群 |
| `task` | 事务任务 | 事务型：信息收集、填表、接龙、截图上报、团课学习、班会签到（要做一个动作，但不是课程作业） | 班群/班干部群 |
| `notice` | 通知 | 其他正式通知：停水停电、放假、缴费、调课、场馆关闭（仅需知晓） | 任意群 · 辅导员/教务处 |
| `chat` | 闲聊 | 寒暄、灌水、表情包、与信息无关 | 任意 |

**边界判据**（写进题干，供 JEV 区分）：

- `lecture` vs `task`：去参加 vs 做一个动作
- `homework` vs `task`：课程提交物 vs 事务动作
- `competition` vs `research`：评选/排名性质 vs 项目制流程（立项→阶段→结题）
- `notice` vs `task`：仅需知晓 vs 需要动作

**cat2（次类别）**：与 cat 同集的第二次 choice，选与 cat 相同 = 无次类。解决跨界消息（"数学建模竞赛宣讲会" = lecture + competition），两类订阅者都能收到。

**urg 等级**（score 0-3）：0 无时限或闲聊 / 1 本周内需关注 / 2 三天内需行动 / 3 当天截止或已截止。

## L2 · JEV 根调用（1 次 6 题）

**所有独立判断塞进一次调用**——题数在 1~16 间几乎不增加成本（同一份 state），拆多次顺序调用只是白加延迟。

```json
{
  "model": "NeoHorse-Jev-4B",
  "state": "【群：计科2201班群（画像：课程群·无绑定课程）】【发送者：学习委员-小陈（学生干部）】@全体成员 高等数学(下)第五章习题册作业已发布，请于11月15日(周五) 23:59 前提交至学习通，逾期不计分。",
  "questions": {
    "is_info": { "type": "noul", "instructions": "是否包含学生需要知晓或采取行动的实质性信息（排除寒暄、灌水、纯表情、无实质内容的转发）" },
    "cat": { "type": "choice", "criteria": {
      "homework": "课程作业、实验、报告、习题提交",
      "exam": "考试安排、补考、成绩、考点范围",
      "competition": "学科竞赛、创业大赛、招新选拔",
      "research": "科研训练项目（SRTP/大创/国省创）流程：立项、选题、开题、中期、结题、分数",
      "exchange": "国际交流、访学、交换、国际会议、奖学金",
      "lecture": "参加型活动：讲座、宣讲会、大会、团建、集合",
      "task": "事务任务：信息收集、填表、接龙、截图上报、团课学习",
      "notice": "其他正式通知：停水停电、放假、缴费、调课",
      "chat": "寒暄、灌水、表情、与信息无关" } },
    "cat2": { "type": "choice", "criteria": { "同 cat 九类；选与 cat 相同表示无次要类别" } },
    "urg": { "type": "score", "criteria": ["无时限或闲聊", "本周内需关注", "3 天内需行动", "当天截止或已截止"] },
    "has_ddl": { "type": "noul", "instructions": "是否包含具体或可推算的截止时间（如 11月15日 23:59、本周五前、两周内）" },
    "action": { "type": "choice", "criteria": {
      "submit": "需要提交作业/作品/材料", "signup": "需要报名或注册",
      "attend": "需要出席或参加", "know": "仅需知晓，无需行动" } }
  }
}
```

**state 模板**：`【群：{group_name}（画像：{kind}{·绑定课程 course}）】【发送者：{sender_card}（{role}）】{text}`——画像写入 state 当 JEV 上下文；课程群已绑课程时 JEV 知道语境，`course` 字段免识别。

**用法要点**：

- `choice` 返回 probabilities：前两名接近 → `low_conf` 进人工复核队列（免费质检信号）
- state 自行截断到 ~1500 字 + 截断标记（上游 422 不静默截断）
- 丢弃条件：`is_info` 低于阈值（初值 0.6）或 `cat = chat`
- 后备方案（金标准集准确率不达标时再启用）：后三题（urg/has_ddl/action）下沉到 L3 分支，代价是正类消息多一次调用

## L3 · 分支问题组（按 cat 条件触发）

只对通过 L2 的消息发起第二次 JEV 调用，成本 ≈ 正类消息数。

| cat | 分支问题 | 说明 |
|---|---|---|
| homework / exam | `channel`（chaoxing/yuketang/email/offline/other）；`exam_type`（期末/期中/补考/四六级/其他，仅 exam） | **画像已绑课程的群跳过课程识别**；未绑课程才做候选课程 noul（别名词典预筛 1~3 门，上限 16 题） |
| competition | `reg_ddl`（报名截止?）/ `final_ddl`（作品截止?）/ `team`（是否组队?）三个 noul | 双 deadline 场景 |
| research | `stage`（choice：立项发布/选题申报/开题/中期检查/结题答辩/分数公告） | SRTP 项目生命周期 |
| exchange | `program_type`（交换/访学/会议/奖学金/其他）/ `eligibility`（限年级专业?） | |
| lecture | `format`（线上/线下）/ `signup`（需报名?） | |
| task | `form_channel`（接龙/问卷星/邮件/线下）/ `scope` | |
| notice | `scope`（全校/院/班） | |
| chat | 无（L2 即丢弃） | |

**定义深、实现浅**：分支结构一次定全（题干占位），先实现 homework/exam 分支；其余等金标准集攒出标注数据再填题干——没有标注数据的分支问了也是瞎问。

**候选课程识别（未绑课程群）**：课程别名词典（"高数/高等数学/微积分"→ 高等数学）在原文做字面匹配，命中的 1~3 门课变成 noul 问题让 JEV 确认；词典未命中时只剩 channel 题。

## L4 · 信息提取（Chat 小模型，按需触发）

**触发器**（全部满足才调用）：该字段规则未拿到 ∧ `has_ddl` 高于阈值（或该类别需要）∧ 原文 ≤1500 字。

| cat | 提取字段（开放集） |
|---|---|
| homework | deadline |
| exam | exam_time |
| competition | deadlines[报名, 作品]（**注意配对**） |
| research | deadline |
| exchange | deadline |
| lecture | time + place |
| task | deadline |
| notice | 通常无 |
| chat | 无 |

**契约**：

```
输入: 原文 + 正则提取到的候选时间片段（或空）
输出: {"deadline": "2026-11-15T23:59:00+08:00" | null, "raw_expr": "本周五前", "confidence": 0.0-1.0}
硬约束: 禁止携带任何思考参数（neohorse-1-9b 400 坑）
回落链: 解析失败 → 带错误重试 1 次 → 正则结果 → "截止时间见原文" + low_conf 进复核队列
```

DDL 规则兜底（L4 之前先跑）：正则 + 中文日期解析（Python `dateparser` / `chrono`）提"11月15日 23:59""本周五前"这类；**提取不到就只推原文 + 紧急度，不硬猜**——猜错的截止时间比没有更糟。

## 发送者过滤（L1a，可选有损）

**四原则：默认关闭 · 可 dry-run · 可审计 · 一键恢复。** 过滤只发生在分类之前，不改变分类与分发语义。

- **用途是限流保命，不是提准**：避免达到 JEV 并发/容量限制（429）的最后一道静态闸
- **黑名单优先于白名单**：黑名单只丢已知噪音（营销号、刷屏机器人），代价近乎零；白名单"只信这几个人"会漏掉转发通知的普通同学——只有 dry-run 报告显示收益远大于代价时才开
- **角色表达优先于 user_id**：`allow: [课程老师, 辅导员]` 耐换届；user_id 留给个别例外（如拉黑某个营销号）
- **顺序在去重之前**（见 architecture.md 不变量 2）
- dry-run：只记录不滤除，24h 后报告"该滤掉 N 条，其中 M 条含预筛关键词命中"——M 就是开启后的已知漏报基线，先看数再决定
- audit：持续复盘"被滤消息里有关键词命中的清单"

## 限流防线（从无损到有损）

1. **去重**（免费）——砍重复转发
2. **关键词预筛**（免费）——砍灌水；预筛词 = 通用词 ∪ 画像词（只画像词会在课程群漏掉转发的竞赛通知）
3. **发送者过滤**（免费但有损，可选默认关）
4. **有界并发队列 + 指数退避**——429 的正面防线；traceId 留档；超时请求按内容 hash 幂等，不无条件重试
5. **压力降级**——队列积压/429 频繁时临时切"仅关键词强命中"或 digest-only，按群公平降级：**宁可晚到，不可静默丢**

## 阈值校准方法

- **noul 概率不是校准正确率**（API 文档原话）：阈值不拍脑袋——先人工标 200~500 条真实群消息，看分数分布再定（如 0.7），标注集留下当回归测试
- **金标准集**：30~50 条真实课程通知（从任何渠道复制的真通知），贴进测试群或存文件；同时是验收基准、调 prompt 依据、回归测试
- **稳定性抽检**：同一批消息隔天重跑，输出抖动大的字段只能进 Digest，不能触发即时推送
- **跨画像冲突样本单独统计**（画像先验与内容判断不一致的消息）——画像设计的风向标，金标准集里专门留一批
